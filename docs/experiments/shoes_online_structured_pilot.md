# Shoes 在线 Qwen3.7-Flash 结构化文本对照

本次是文本生成与自检的低成本诊断，不是检索结果。原 Shoes 队列继续使用本地 Qwen3-VL-8B-Instruct；在线结果存放在独立目录，不替换原生成文件，也未加入新的检索训练。

## 原有方法与 FashionIQ 的区别

FashionIQ Dress 已有在线 `qwen3.7-flash` 生成的 train/val 结构化文件。当前 Shoes 主实验实际使用本地 Qwen3-VL-8B-Instruct，并非在线 Flash。

输入都是**参考图＋修改句**，不向模型发送真实目标图、目标 ID 或目标描述。目标 ID 仅作为本地结果绑定元数据。参考图最长边 512；生成最多 768 token，自检最多 256 token。

输出 `retain/remove/add`、`relations`、`target_description`、`complexity`、`confidence`；属性项包含 `attribute/category/region/evidence`。随后检查字段格式，再单独调用同一模型检查语义。不通过则保留失败记录，主训练回退到 DQU。自检是模型信号，不能称为独立模型、人工标注或真值。

Shoes 使用 `generate_benchmark_edits.py` 的鞋类提示词，不沿用 FashionIQ 的服装排除规则。直接套用旧 FashionIQ API 脚本会误用其语义清洗器，所以本次复用通用 schema，单独实现 Shoes 在线入口。

## 24 条固定图文查询对照

从已有本地生成快照的 1,296 条记录中，seed=42 固定抽取 12 条本地通过＋12 条本地失败的 train 查询。属于有意包含失败的诊断样本，不能估计整个数据集的准确率。本地文件 SHA-256、查询绑定及索引保存于 `pilot.json`。

| 方案 | 字段校验通过 | 自检通过 |
|---|---:|---:|
| 已保存本地 8B 输出 | 22/24 | 12/24（抽样规则决定） |
| 在线 Flash，原 Shoes 提示词 | 0/24 | 0/24（字段不合格，未调用自检） |
| 在线 Flash，改进生成提示词＋原自检 | 24/24 | 12/24 |
| 同一份改进生成文本＋改进自检 | 24/24 | 20/24 |

在线各组使用相同模型、JPEG 参考图、非思考模式、temperature=0、`json_object`、token 上限。最后两组**逐条复用完全相同的生成文本**，只更换自检提示词，不重复计生成费用。本地与在线的模型、图片编码、JSON 输出模式有差异，因此不能将其差值解释为单一因素的因果效果。

原提示词的 0/24 是严格字段兼容性结果，不能解释为在线模型完全不会生成语义文本。常见错误是 `evidence="instruction"` 或自由文本、类别为 `material/color`、缺失字段；2 条生成达到 token 上限。此次保留原始输出，未像旧 FashionIQ 脚本那样自动修复 evidence 枚举，因此通过率也不能直接与其历史结果比较。

官方文档说明：多模态请求即使指定 `json_schema` 也会退化为 `json_object`，只能保证 JSON 格式，不保证本项目 schema。必须保留本地校验：[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

## 实际尝试的优化

1. 明确单选枚举和完整字段；限制每组属性数，避免冗长输出与截断。
2. 明确描述**指令要求的目标状态**。保留“比参考图更浅、更尖、更粗”等相对关系，不能擅自变成白色、精确数量或特定材质。
3. 自检明确“参考图不是目标图”，不因参考图尚未发生变化而否定编辑计划。仍拒绝编造细节、替换方向错误和互相矛盾的属性。
4. 再对 8 条事后选出的困难案例尝试更保守的生成和自检：修改属性覆盖冲突的 retain；“有粉色”只要求存在粉色，不强制替换全部红色；不臆定双色分布；多鞋拼图只保留共同结构；目标描述直接写最终状态。

第 4 项是依据首轮错误设计的回归检查，不是独立验证集。复核仅使用参考图和指令；相关观察属于本次助手视觉审阅，不是独立人工 GT，也没有读取目标图来评价生成准确率。

8 条检查的字段和自检均为 8/8 通过，但仍有应暂缓使用的案例：58 将含糊的“鞋底上方开口”具体化为脚床下方的孔；236 为“黑红”额外保留米色侧面；484 要求纯红鞋面却保留粉色鞋带。这些是助手审阅发现的风险，不是根据真实目标图得出的准确率。改提示词和再自检无法完全消除幻觉，不能把 8/8 当作质量保证。

下一阶段建议按固定规则记录冲突/歧义并回退原文本或 DQU，而不是删除困难查询；所有验证查询仍须参与完整评估。多鞋拼图、全局颜色约束、未指定的颜色位置应优先抽查。模型自报 confidence 不能直接视为已校准的正确概率；要用独立人工复核样本校准。全量在线生成应建立新版本，不与本轮本地生成静默混合。

## 成本与密钥处理

首轮 24 条共 96 次请求，输入 46,330 token、输出 28,027 token；按北京区间 ≤32k 标价估算 **0.0316876 元**，无缺失 usage。实际账单可能受账户优惠影响。

[官方模型价格](https://help.aliyun.com/zh/model-studio/qwen3-7-flash) 为输入 0.2 元/百万 token、输出 0.8 元/百万 token。本次不开启思考，参考图缩至最长边 512，不自动重试。首轮与后续 8 条检查**共用**最多 128 次请求、0.5 元的保守预留预算，未知失败请求也保留预算占用；不是每阶段重新获得 0.5 元额度。

全部完成后合计 **112 次请求**，输入 **57,976**、输出 **32,684** token，usage 均完整；标价估算合计 **0.0377424 元**。第二轮增加 16 次请求，估算 **0.0060548 元**。保守预留累计 0.4128768 元，实际 token 估算明显低于预留；没有继续扩大全量生成。

密钥通过交互式隐藏输入进入进程内存，仅放在官方 HTTPS 接口的鉴权头。代码不接受密钥命令行参数，不写环境文件或日志，不上传 Git。接口限制官方域名、验证 TLS、禁止重定向和代理转发；保存文本时脱敏。单次 HTTP/网络失败即停，避免盲目重试计费。
